# Decisions log

Format: **[step] Decision** — why. `DEFAULTED – owner may override` marks choices made without asking that are cheap to change.

## Step 01
- **[01] Keep Unity 6000.6.7f1 and the URP 2D template as-is.** Plan A9: never upgrade; template is already 2D.
- **[01] Owner's existing `.gitignore`/`.gitattributes` kept** (GitHub Unity templates, already LFS-ready); appended `.DS_Store`, `BalanceReports/`, `TestResults/`, dotnet `bin/obj`. `.DS_Store` untracked.
- **[01] Extra assembly `Game.App`** (Unity glue + composition root: `GameBootstrap`, `SceneLoader`, save lifecycle hooks, debug overlay/console). `Game.Core`, `Game.Save` and `Game.Services` are all `noEngineReferences: true`. Why: services stay pure C# and testable outside Unity; overview said "services live in a Unity assembly only for glue" – the glue is now its own assembly.
- **[01] Config flows SO → Core POCOs.** `Game.Data` ScriptableObjects are converted by `ConfigDatabase` into a pure `GameDatabase` (Core) exposed via `IConfigProvider`. Services depend on Core config models, not on ScriptableObjects. Why: keeps Services engine-free and lets tests build configs in code.
- **[01] Logger interface named `IGameLogger`** (not `ILogger`) to avoid clashing with `UnityEngine.ILogger` in files that import both namespaces.
- **[01] RNG = own `SeededRandom` (xoshiro128\*\* seeded via SplitMix64)** instead of wrapping `System.Random`. Why: `System.Random` output differs between runtimes (Mono/IL2CPP/.NET), we need identical results across platforms, editor, tests and saved RNG state.
- **[01] Editor namespace is `Game.EditorTools`** (assembly still `Game.Editor`) to avoid shadowing `UnityEditor.Editor`.
- **[01] Nullable reference types not enabled** in Unity assemblies (would flood the console with warnings in a mixed codebase); enabled only in the dotnet harness projects is also skipped for consistency. DEFAULTED – owner may override.
- **[01] Dual test harness:** Unity Test Framework (source of truth, run in batch mode) + `DotnetTests/` (netstandard2.1 library linking Core/Save/Services sources + NUnit test project) for fast iteration and coverage numbers.
- **[01] Package id `com.andreitdr.squadfight`, company `andreitdr`, product `SquadFight`.** DEFAULTED – owner may override (game name not final).
- **[01] Android: min API 26 (template value, ≥ Unity 6 minimum), target API 36, IL2CPP, ARM64 only. iOS: IL2CPP, min iOS 15.0 (template).**
- **[01] UI is built in code** (uGUI hierarchy created by a `UIFactory` driven by a `Theme` asset) rather than hand-authored prefabs. Why: autonomous development, reviewable diffs, no fragile prefab YAML; art stays swappable through Theme/config sprite refs.

## Step 02
- **[02] Content is authored as CSV** (`Content/Source/*.csv`, schema in `CONTENT_SCHEMA.md`) and imported by an idempotent importer that creates/updates ScriptableObjects by id. Why: compact, diffable, spreadsheet-friendly; it is the step-15 importer started early and doubles as "Create Sample Content".
- **[02] SO cross-references are object references** (hero→skills, fight→enemies/tables/beats, chapter→fights); **drop entries reference by string id** (`refId`). Why: drag-and-drop safety for the common links, simple tables for drops; validator checks both.
- **[02] GameConfig lives in `Assets/_Game/Resources/GameConfig.asset`** and Boot loads it with `Resources.Load`. Fights, enemies, skills, story beats and drop tables are gathered transitively from heroes/chapters (plus optional `extra*` lists), so a designer only adds the root asset to a list.
- **[02] Star levels have a `currencyCost`** in addition to shards. Why: gold otherwise has no sink in v1 (no shop/crafting). Set to 0 to disable. DEFAULTED – owner may override.
- **[02] Validator is pure Core (`ConfigValidation`)** + editor wrapper for asset checks (missing sprites, null list entries, orphan assets, file name ≠ id). Unobtainable heroes / unused assets are warnings, not errors.
- **[02] Placeholder art is procedural** (white shapes tinted per hero/enemy/rarity via `tint` colour), generated by `Tools/Game/Content/Generate Placeholder Art`, labelled `placeholder` in the AssetDatabase.
- **[02] Roster (placeholder content, owner may rename):** 10 heroes — Common: Aldric (knight), Lyra (archer), Pip (apprentice mage); Uncommon: Sister Maren (cleric), Vex (rogue); Rare: Seraphine (paladin), Kael (hunter); Epic: Zara Stormcaller, Fennick (bard); Legendary: Drakon (dragon knight). ## Step 03
- **[03] Newtonsoft JSON** (Unity package 3.2.2) over System.Text.Json (not available in Unity's .NET Standard 2.1 profile). camelCase, enums as strings (robust to enum reordering), `DateParseHandling.None`, `ObjectCreationHandling.Replace`.
- **[03] Envelope** `{format, version, counter, savedUtc, sha256(counter:payload), payload-as-string}`. No obfuscation (offline; cheating is the player's choice).
- **[03] Recovery rule:** newest intact of main/tmp by counter → bak → new game. Damaged files moved to `save.corrupt.<ts>.<uid>.<name>` (newest 5 kept). Intact files this build cannot read (future version, unknown format, unknown enum value, failed migration) and IO read errors make the session **read-only** instead of being replaced by a new game.
- **[03] Debounce = at most 1 s after the *first* unsaved change** (not trailing), plus flush on pause/focus loss/quit.
- **[03] Sample migration v1→v2** renames hero `star`→`stars`; fixture `Tests/Fixtures/save_v1.json`. Current save version = 2.
- **[03] link.xml** preserves Game.Core/Game.Save for IL2CPP stripping (device smoke test still pending).
- **[03] High-stakes review** by a subagent found 7 issues (unreadable save treated as corrupt → new game overwrite; IO read error treated as corruption; Decode could throw; SaveNow before Load; throwing handlers; tmp not promoted; date-string coercion; unchecked counter; quarantine collisions). All fixed + regression tests.

## Step 04
- **[04] Mutation protocol:** validate → apply → `ServiceContext.Commit()` (MarkDirty) → `Emit` event. `BeginTransaction()` snapshots `SaveData`, defers events and the dirty mark, restores on dispose without `Complete()` – used by RewardService for atomic grants.
- **[04] Read-only views** for UI are snapshot structs (`HeroInfo`, `ItemInfo`), not the save objects.
- **[04] Party:** fixed-length list (nulls = empty). Assigning a hero already in the party moves/swaps it rather than failing. An empty party is allowed in the service; starting a fight requires ≥1 member.
- **[04] RNG state** is saved with the player state so drop sequences continue across restarts (no free re-rolls by restarting).
- **[04] `SaveReconciler`** runs after every load to adapt old saves to new content (adds heroes, clamps stars, fixes equip links, removes duplicate instance ids).

## Step 05
- **[05] D1 consume shards on unlock, manual unlock, D2 overflow → gold** (approved defaults). Leftover shards are converted the moment max star is reached (they could never be used).
- **[05] Star-up shard cost = ceil(star table cost × rarity starCostMultiplier)**, plus the star level's currency cost.
- **[05] Debug `unlock <hero> force`** grants the missing shards first (handy for QA).

## Step 06
- **[06] Roll variation off by default** (flag + percent in config.csv). Rolled values are stored in the save and never change.
- **[06] D3 no inventory limit** (approved default). When a limit is configured, `AddItem` returns InventoryFull (reward handling decided in step 10).
- **[06] Item instance ids are v4-format GUIDs from the game RNG**, so seeded simulations and tests are fully deterministic.
- **[06] Auto slot choice:** first empty compatible slot, else replace the first compatible slot; moving an item from another hero or another slot is allowed (no duplication). Selling: rarity `itemSellValue` gold, blocked while equipped.
- **[06] Content:** 24 templates = 6 slot kinds × 4 tiers (Common/Uncommon/Rare/Epic templates; any template can drop at any rarity, Legendary via rarity weights).

## Step 07
- **[07] Pipeline** `final = (base × star + flat) × (1 + percent)`; combat buffs add to the percent term (step 08). HP/damage are integers (round half away from zero); min-damage floor before crit.
- **[07] Power weights** MaxHp 0.1, Attack 1, Defense 0.8, Speed 0.5, CritChance 100, CritDamage 20 (content; tuned in step 15).

## Step 08
- **[08] Round-based turn order** (all living units once per round by speed→slot→id); max rounds = turns cap (100 → Timeout = defeat).
- **[08] Cooldowns tick at the end of the holder's turn**; statuses/shields count the holder's turns (own-turn application skips one tick so "2 turns" means 2 full turns).
- **[08] Enemy stat multipliers do not scale speed** (keeps turn order readable across chapters).
- **[08] Flat `BattleEvent` records** (index-based) instead of a class hierarchy: trivial to hash, log and replay.

## Generated art & dialogue (owner request, 2026-10-30)
- **Art is generated, not hand-painted**: `tools/art/` draws every sprite as layered SVG (chibi cut-out rig, gradients + ink outlines) and rasterises it with resvg. Output in `Assets/_Game/Art/Generated/` (labelled `generated-art`, not `placeholder`). Regenerating is deterministic.
- **Battle animation = frame-by-frame sprites** (`SpriteAnimSet`, 6 clips per character, ~37 frames) played by `SpriteAnimator` on the uGUI unit image, instead of Unity Animator/2D Animation rigs: zero runtime setup, trivially swappable, and the frames include baked FX (swooshes, auras, tip glows). 360 px frames, 512 px for bosses.
- **Swappable by design**: definitions/Theme gained optional art slots; every widget falls back to the old tinted shapes when a slot is empty. `Tools/Game/Art/Apply Generated Art` only fills empty/generated/placeholder slots, so hand-assigned art is never overwritten.
- **9-slices stay grayscale** so the Theme colors (and button styles/tab highlights) keep working; icons, gems, stars, cards and characters are full color and drawn untinted.
- **Hero cards are layered at runtime** (rarity back + 3:4 bust + ornate frame + gem + class icon + localized name) so names stay localized; `Art/Generated/Cards/` holds baked versions for showcase/store use only.
- **Dialogue barks live in `Resources/Localization/strings_dialogue.csv`** (`line_<id>_<trigger>_<n>`), loaded by the existing CSV localizer; no importer change. Barks are presentation-only (UnityEngine.Random), rate-limited, and suppressed above ×3 speed and during skip, so they never affect the deterministic simulation.
- **Story**: 21 new beats (hero introductions + banter) in `story.csv`, attached via `fights.csv`.
- **Logo/text** use Liberation Sans (OFL, already in the project); no new third-party assets were added.

## Android APK releases on GitHub (owner request, 2026-10-31)
- **Release trigger = pushing a `v<version>` tag** (or creating a GitHub Release with a new tag). CI builds a signed APK and AAB in one Editor session (`BuildScript.BuildAndroidReleaseAll`, shared versionCode) and attaches both to the GitHub Release via `softprops/action-gh-release`.
- **Tag must equal `VERSION.txt`**: one source of truth for the version name; the job fails early with a hint otherwise.
- **The APK is release-signed with the upload keystore, never debug-signed**: a debug key differs per CI runner, so phones would refuse updates over a previous install. No keystore secrets → the build fails with the BUILD.md hint.
- **Local keystore path is cleared from PlayerSettings after each Android build** so it never lands in `ProjectSettings.asset`.
- **LFS objects cached in the release job** to save LFS bandwidth quota.

## Tutorial fixes from the iOS Simulator play-test (2026-10-31)
- **Tutorial resumes from a screen reachable from Home**: each step has a resume point (deeper hero/equip steps restart at the Heroes tab) and an "already done" check (hero unlocked, in party, weapon equipped, fight cleared) so a restart never waits on a button that no longer exists. Popup steps are skipped together with the action that opens them.
- **Tutorial fights are tuned for the scripted party, not the casual simulator**: `BalanceCli tune tutorial` sets fight 1-1/1-2 so the exact tutorial party wins without losing a hero ≥ 95% of the time (multipliers 2.03→1.47 and 1.73→1.18). Low-HP focus-fire AI is unchanged; later fights keep their casual-player targets.
- **Power warning only below 90% of the recommendation**: recommended power is the median casual player's power, so 90–100% shows a caution colour without the "too weak" text (the tutorial party is at 97% for fight 1-2).
- **Tutorial hint stays off popup panels** (below the panel if there is room, else above).

## Release and pre-release builds (owner request, 2026-10-31)
- **Pushes to `main` never build an APK**: they run tests only. Android builds run only for version tags.
- **Defence in depth**: the workflow is read-only by default (`contents: read`); only the tag-gated release job may write, and it also fails fast and skips publishing if it ever runs without a tag.
- **GitHub only, no stores**: releases and pre-releases are signed APKs on GitHub Releases; CI builds no AAB and uploads nothing to Google Play / App Store (supersedes the APK + AAB release job).
- **Two channels by tag**: `vX.Y.Z` → release (GitHub "Latest"); `vX.Y.Z-(alpha|beta|rc)[.]N` → pre-release (dot optional; the first pre-release is `v0.0.1-alpha1`) (GitHub "Pre-release", never "Latest"). Other `v…` tags are rejected by the job. The tag must equal `VERSION.txt`.
- **Pre-releases are release-signed, not development builds**: same upload key as releases, so testers can update from a beta to the release without uninstalling (a debug-signed dev build could not be updated in place).
- **iOS version name drops the pre-release suffix** (`1.1.0-beta.1` → `1.1.0`) because CFBundleShortVersionString accepts digits and dots only.

## APKs built locally, CI tests only (owner request, 2026-10-31; supersedes the tag-based release job above)
- **CI no longer builds Android or iOS** and has no release job or tag trigger; it only runs tests on pushes to `main` and PRs. Its token is read-only for contents, so it cannot publish a release.
- **A signed release APK is built on the owner's Mac after every push to `main`** (`tools/build-apk.sh`); the owner uploads it to GitHub Releases by hand (pre-release for `-alpha/-beta/-rc` versions). GitHub only, no stores.
- **Keystore password only in the macOS Keychain**: `tools/build-apk.sh setup` lets the owner type it into `keytool` and `security` in their own terminal; builds read it from the Keychain, so it is never in the repo, CI secrets or chat. The keystore (`~/.squadfight/`) stays outside the repo.

## No GitHub CI: tests run locally (owner request, 2026-10-31; supersedes the CI decisions above)
- **`.github/workflows/ci.yml` removed**: nothing runs on GitHub. `tools/test-all.sh` runs every suite (dotnet tests, BalanceCli validate + progression, Unity EditMode + PlayMode) on the Mac before each push to `main`; the signed APK is still built locally after each push (`tools/build-apk.sh`).
- **No Unity license / keystore secrets on GitHub** are needed any more.

## No battle skip (owner request, 2026-10-31; supersedes "Skip" in plan/13 and MILESTONE-M2)
- **The battle HUD has no Skip button**: battles always play out; speed ×1/×2/×3, Auto and Pause → Retreat remain. `BattleFlow.Finish` still runs any remaining turns instantly at the service level (used by tests and flows that never open the battle screen).
