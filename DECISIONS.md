Format: **[step] Decision** — why. `DEFAULTED – owner may override` marks choices made without asking that are cheap to change.

## Step 01
- **[01] Keep Unity 6000.6.7f1 and the URP 2D template as-is.** Plan A9: never upgrade; template is already 2D.
- **[01] Owner's existing `.gitignore`/`.gitattributes` kept** (GitHub Unity templates, already LFS-ready); appended `.DS_Store`, `BalanceReports/`, `TestResults/`, dotnet `bin/obj`. `.DS_Store` untracked.
- **[01] Extra assembly `Game.App`** (Unity glue + composition root: `GameBootstrap`, `SceneLoader`, save lifecycle hooks, debug overlay/console). `Game.Core`, `Game.Save` and `Game.Services` are all `noEngineReferences: true`. Why: services stay pure C# and testable outside Unity; overview said "services live in a Unity assembly only for glue" – the glue is now its own assembly.
- **[01] Config flows SO → Core POCOs.** `Game.Data` ScriptableObjects are converted by `ConfigDatabase` into a pure `GameDatabase` (Core) exposed via `IConfigProvider`. - **[01] RNG = own `SeededRandom` (xoshiro128\*\* seeded via SplitMix64)** instead of wrapping `System.Random`. Why: `System.Random` output differs between runtimes (Mono/IL2CPP/.NET), we need identical results across platforms, editor, tests and saved RNG state.
- **[01] Editor namespace is `Game.EditorTools`** (assembly still `Game.Editor`) to avoid shadowing `UnityEditor.Editor`.
- **[01] Nullable reference types not enabled** in Unity assemblies (would flood the console with warnings in a mixed codebase); enabled only in the dotnet harness projects is also skipped for consistency. DEFAULTED – owner may override.
- **[01] Dual test harness:** Unity Test Framework (source of truth, run in batch mode) + `DotnetTests/` (netstandard2.1 library linking Core/Save/Services sources + NUnit test project) for fast iteration and coverage numbers.
- **[01] Package id `com.andreitdr.squadfight`, company `andreitdr`, product `SquadFight`.** DEFAULTED – owner may override (game name not final).
- **[01] Android: min API 26 (template value, ≥ Unity 6 minimum), target API 36, IL2CPP, ARM64 only. iOS: IL2CPP, min iOS 15.0 (template).**
- **[01] UI is built in code** (uGUI hierarchy created by a `UIFactory` driven by a `Theme` asset) rather than hand-authored prefabs. Why: autonomous development, reviewable diffs, no fragile prefab YAML; art stays swappable through Theme/config sprite refs.

## Step 03

Intact files this build cannot read (future version, unknown format, unknown enum value, failed migration) and IO read errors make the session **read-only** instead of being replaced by a new game.
- **[03] Debounce = at most 1 s after the *first* unsaved change** (not trailing), plus flush on pause/focus loss/quit.
- **[03] Sample migration v1→v2** renames hero `star`→`stars`; fixture `Tests/Fixtures/save_v1.json`. Current save version = 2.

## Step 04
- **[04] Mutation protocol:** validate → apply → `ServiceContext.Commit()` (MarkDirty) → `Emit` event. `BeginTransaction()` snapshots `SaveData`, defers events and the dirty mark, restores on dispose without `Complete()` – used by RewardService for atomic grants.
- **[04] Read-only views** for UI are snapshot structs (`HeroInfo`, `ItemInfo`), not the save objects.
- **[04] Party:** fixed-length list (nulls = empty). Assigning a hero already in the party moves/swaps it rather than failing. An empty party is allowed in the service; starting a fight requires ≥1 member.
- **[04] RNG state** is saved with the player state so drop sequences continue across restarts (no free re-rolls by restarting).
- **[04] `SaveReconciler`** runs after every load to adapt old saves to new content (adds heroes, clamps stars, fixes equip links, removes duplicate instance ids).

## Generated art & dialogue (owner request, 2026-10-30)
- **Art is generated, not hand-painted**: `tools/art/` draws every sprite as layered SVG (chibi cut-out rig, gradients + ink outlines) and rasterises it with resvg. Output in `Assets/_Game/Art/Generated/` (labelled `generated-art`, not `placeholder`). Regenerating is deterministic.
- **Battle animation = frame-by-frame sprites** (`SpriteAnimSet`, 6 clips per character, ~37 frames) played by `SpriteAnimator` on the uGUI unit image, instead of Unity Animator/2D Animation rigs: zero runtime setup, trivially swappable, and the frames include baked FX (swooshes, auras, tip glows). 360 px frames, 512 px for bosses.
- **Swappable by design**: definitions/Theme gained optional art slots; every widget falls back to the old tinted shapes when a slot is empty. `Tools/Game/Art/Apply Generated Art` only fills empty/generated/placeholder slots, so hand-assigned art is never overwritten.
- **9-slices stay grayscale** so the Theme colors (and button styles/tab highlights) keep working; icons, gems, stars, cards and characters are full color and drawn untinted.
- **Hero cards are layered at runtime** (rarity back + 3:4 bust + ornate frame + gem + class icon + localized name) so names stay localized; `Art/Generated/Cards/` holds baked versions for showcase/store use only.
- **Dialogue barks live in `Resources/Localization/strings_dialogue.csv`** (`line_<id>_<trigger>_<n>`), loaded by the existing CSV localizer; no importer change. Barks are presentation-only (UnityEngine.Random), rate-limited, and suppressed above ×3 speed and during skip, so they never affect the deterministic simulation.
- **Story**: 21 new beats (hero introductions + banter) in `story.csv`, attached via `fights.csv`.
- **Logo/text** use Liberation Sans (OFL, already in the project); no new third-party assets were added.

## Android APK releases on GitHub (owner request, 2026-10-31)
- **Release trigger = pushing a `v<version>` tag** (or creating a GitHub Release with a new tag). CI builds a signed APK and AAB in one Editor session (`BuildScript.BuildAndroidReleaseAll`, shared versionCode) and attaches both to the GitHub Release via `softprops/action-gh-release`.
- **Tag must equal `VERSION.txt`**: one source of truth for the version name; the job fails early with a hint otherwise.
- **The APK is release-signed with the upload keystore, never debug-signed**: a debug key differs per CI runner, so phones would refuse updates over a previous install. No keystore secrets → the build fails with the BUILD.md hint.
- **Local keystore path is cleared from PlayerSettings after each Android build** so it never lands in `ProjectSettings.asset`.
- **LFS objects cached in the release job** to save LFS bandwidth quota.

Popup steps are skipped together with the action that opens them.

## Release and pre-release builds (owner request, 2026-10-31)
- **Pushes to `main` never build an APK**: they run tests only. Android builds run only for version tags.
- **Defence in depth**: the workflow is read-only by default (`contents: read`); only the tag-gated release job may write, and it also fails fast and skips publishing if it ever runs without a tag.
- **GitHub only, no stores**: releases and pre-releases are signed APKs on GitHub Releases; CI builds no AAB and uploads nothing to Google Play / App Store (supersedes the APK + AAB release job).
- **Two channels by tag**: `vX.Y.Z` → release (GitHub "Latest"); `vX.Y.Z-(alpha|beta|rc)[.]N` → pre-release (dot optional; the first pre-release is `v0.0.1-alpha1`) (GitHub "Pre-release", never "Latest"). Other `v…` tags are rejected by the job. The tag must equal `VERSION.txt`.
- **Pre-releases are release-signed, not development builds**: same upload key as releases, so testers can update from a beta to the release without uninstalling (a debug-signed dev build could not be updated in place).
- **iOS version name drops the pre-release suffix** (`1.1.0-beta.1` → `1.1.0`) because CFBundleShortVersionString accepts digits and dots only.

## APKs built locally, CI tests only (owner request, 2026-10-31; supersedes the tag-based release job above)
- **CI no longer builds Android or iOS** and has no release job or tag trigger; it only runs tests on pushes to `main` and PRs. Its token is read-only for contents, so it cannot publish a release.
- **A signed release APK is built on the owner's Mac after every push to `main`** (`tools/build-apk.sh`); the owner uploads it to GitHub Releases by hand (pre-release for `-alpha/-beta/-rc` versions). GitHub only, no stores.
- **Keystore password only in the macOS Keychain**: `tools/build-apk.sh setup` lets the owner type it into `keytool` and `security` in their own terminal; builds read it from the Keychain, so it is never in the repo, CI secrets or chat. The keystore (`~/.squadfight/`) stays outside the repo.

## No GitHub CI: tests run locally (owner request, 2026-10-31; supersedes the CI decisions above)

- **No Unity license / keystore secrets on GitHub** are needed any more.

## "The Hundred": story, 100 heroes, 40 chapters, side quests (owner request, 2026-10-31)
Owner answers: unique active **and** passive per hero; 40 chapters × 9–11 fights (random); rarity random per hero but meaningful; dark-epic tone; spread hero shards more, some fights items-only; side quests for lore and better items that do not count toward chapter completion.
- **Story**: "The Hundred". Seven living hearts (dragon, leviathan, tree, storm, titan, saint, king) hold the Seals over the Hollow; the party kills the first one (the Red Dragon) believing it is the enemy. 8 acts × 5 chapters: Ash Road, Drowned Coast, Thornwild, Glass Desert, Frostmarch, Ironhold, Bloodmoon Abbey, Hollow Throne. Two Seals break, four hold at a price (Ysra's graft, the Weeping Saint kept against her will), and Corvin becomes the last lock. Every hero recruited swears one of the hundred oaths that make the new binding. Chapters 1–3 keep their ids and fights; their beats were rewritten darker (same ids).
- **Combat**: 14 new effect types (DoT burn/poison/bleed, HoT, drain, execute, %HP, taunt, silence, cleanse, dispel, revive, thorns, dodge, cooldown shift, mark) and 4 targeting rules, all deterministic through `IRandom` (no extra RNG draws when a mechanic is absent, so old battles replay the same). **Passives are SkillDefs with a trigger** (same asset type and folder) instead of a new asset type: less plumbing, one parser (`EffectSpec`) for importer and CSV loader. Passives never trigger other passives (no loops).
- **Uniqueness is validated** (`config.uniqueHeroAbilities`): every hero has a passive and no two heroes share an active or passive *behaviour* (effect signature, not name). Off in test fixtures, which share skills on purpose.
- **Rarity rolled per hero** (seed 100, `gen_roster.py`) until every class has strictly fewer heroes at each higher rarity, original 10 heroes included. Result: Tank 8/5/4/2/1, Warrior 6/5/4/3/2, Ranger 9/5/3/2/1, Mage 7/5/4/3/1, Support 7/6/4/2/1 (Common/Uncommon/Rare/Epic/Legendary); all 37/26/19/12/6.
- **Stats** come from a per-class Common template × rarity multiplier (1/1.12/1.33/1.6/1.95) × a random lean (bulky, fierce, swift, keen, stalwart, balanced).
- **Fight counts** rolled with seed 40 (401 main fights). Side quests: 1–3 per chapter as designed (79); chapter 32 has 2 although the roll said 1 (kept the second side quest's lore).
- **Side quests** are fights with `kind=Side` kept in a separate chapter list (`SideQuestIds`), so completion, stars, the unlock chain and "next recommended fight" ignore them with no special cases. They open only through unlock conditions (validator requires one). Each chapter's first side quest drops a unique relic (tier 0, Epic in acts I–III, Legendary after); the others drop gear one rarity band above the main fights. Lore is shown after the first clear and kept in the per-chapter Journal.
- **Shard spread**: each new hero gets 3 targeted grants of 20% of its unlock cost on three different fights of its act (recruitment fight first); random shard drops are limited to the current and earlier acts' heroes (`RandomHeroShardByRarity` refId = origin pool); 89 of 401 main fights are item-only. Aldous, Lisbet and Sunniva are recruited one act early because the story needs them there.
- **Gear tiers**: one tier per act (`equipment.csv` tier; RandomEquipment refId = tier); tier stats grow ×1.38 per act; tier 0 = unique relics, never random. Without hero levels (A6), late-game power comes from gear tiers.
- **Enemies**: 107 new (8 factions, 40 bosses, every boss with a passive). Elite variants reuse their base enemy's art with a tint (`enemies.csv` art column) to keep the build smaller.
- **Balance**: `BalanceCli tune` now fits chapter by chapter (snapshots re-taken after each chapter, so later chapters see the real progression), in parallel, against the **weakest of 6 casual players** (replay each new fight twice, play side quests); targets for their first attempt: normal 0.88 (first fight of a chapter 0.93), bosses 0.8, side quests 0.7, chapter 1 0.92–0.95. A 400-fight campaign assumes some farming: tuning for pure rushers (greedy) left every chapter they could not reach untuned, so `progression` still reports greedy runs but the tune does not target them. The simulator plays side quests (casual/hardcore), sells items that are no upgrade for its party, hardcore replays 5× (was 10×, which hit the 5,000-fight cap), and gives up after 40 straight losses on one fight.
- **Art** (placeholder): new characters are palette/part variations of the original specs, rendered at 288 px frames (400 px bosses) instead of 360/512 to limit build size; chapter 4–40 backgrounds are the three scenes re-seeded with an act colour grade; 9 new status icons; 96 item icons.

## iPad / tablet layout (owner request, 2026-10-31)
Owner: the game must work well on iPad without simply blowing the phone UI up.
- **Canvas from physical size** (`AdaptiveCanvasScaler`): phones keep 1080×1920 / match 0.5 (unchanged). Tablets (h/w ≤ 1.65 — iPad mini is 1.52, 16:10 Android 1.6; phones start at 16:9 = 1.78) get a canvas `width = screen inches × 300 units/inch` (clamped 1300–2400, iPad Retina 264 dpi when the device reports none). Phones run at ~370 units/inch, so tablet UI is ~1.2× its phone size in inches — the same ratio iPadOS uses for points — instead of the ~2× the old rule gave. iPad mini ≈ 1370, iPad 11" ≈ 1895, iPad 13" ≈ 2345 units wide.
- **Use the room, don't stretch it**: screen bodies are centred columns (`MaxSizeFitter`; `ScreenKit.ReadableWidth` 1400 for lists/forms, `WideWidth` 2100 for the Heroes and Bag grids); backgrounds, top bar and tab bar stay full-bleed (tabs grouped in the middle). Pooled grids add columns instead of widening cells (cells grow ≤ 15%, then the grid is centred). Home is a centred column (max 1900 tall); the battle formation stays in a 1300×1700 stage in the middle of the full-screen scene. Popups/toasts already had fixed widths.
- Portrait only on iPad too (`requiresFullScreen`, no Split View) — landscape would need separate layouts. Phones are unaffected: every cap is wider than a phone canvas.

## Enemy ranks, boss specials, player level (owner request, 2026-10-31; steps 02/08/09/10/12/13/15 reworked)
Owner: "add a lot of new enemies; higher ranks have more skills and more HP; Boss is the top rank with special attacks and gives more experience". Owner answers: experience goes to a **player level** (not hero levels; hero power and balance model unchanged); **~60 new enemies with new art**.
- **Five ranks** (`EnemyRank`): Minion < Soldier < Elite < Champion < Boss, in `ranks.csv` (`hpMultiplier` 0.6/1/1.3/1.6/2, `xp` 2/3/5/9/30, `minSkills` 0/1/2/3/4). The validator requires all three to climb rank by rank, and an enemy's skill count (active + passive + extra skills + specials) to fit its rank. `rank` replaces `isBoss` (`IsBoss` = rank Boss; old tables still load).
- **More HP = a battle-time multiplier** on max HP (`BattleSetupBuilder.EnemyStats`), not baked into base stats, so the rule holds for any content. Validator: **in every wave a higher rank has more HP than any lower rank** (what the player compares side by side); the generator builds waves that respect it.
- **More skills**: enemies can have `extraSkills` (actives with their own cooldowns, used after the main active). Champions = active + extra + passive; bosses = active + extra + passive + specials.
- **Boss specials** (`specials`, skills with a `threshold`): each charges once when the boss's HP first drops to its threshold (`SpecialCharged` event, "Charging …!" in battle) and fires on the boss's next turn, ignoring cooldowns and silence; a stun only delays it. Every boss has two (60% and 30% HP). Battle shows a red banner with the special's name.
- **Existing enemies keep their skills**; their rank follows their skill count (0 → Minion, 1 → Soldier, 2 → Elite). The 40 bosses got an extra skill and two specials each (the three original bosses also a passive) — `tools/content/bestiary_design.py`.
- **64 new enemies, 8 per act** (2 Minions, 1 Soldier, 3 Elites, 2 Champions), each with its own generated look (`roster_generated.py`: own keyword list, hero bodies allowed as templates, Champions 8% bigger, Minions 8% smaller). Every enemy is used in fights; Elites appear from a chapter's middle on, Champions in its last third and in side quests.
- **Player level**: XP = rank XP of every enemy defeated (on a defeat or retreat too, for what was killed). `levels.csv` (generated): 60 levels, total XP to level L = 164 × (L−1)^1.3; a casual run ends at ~level 51, hardcore reaches the cap. Each level rolls a reward table (gold + a random shard of the pool of the act a casual player is in at that level; every 5th level also gear). XP and level rewards are granted in the fight's transaction. Save v6 (`player`: level/xp/totalXp); existing saves start at level 1 (`DEFAULTED – owner may override`: no retroactive XP). UI: level + XP bar on Home, "+N XP" / "Level up!" on the result screen, rank and XP in the fight preview, a rank tag over every enemy in battle.
- **Balance**: full `BalanceCli tune`, then `ease 10` (only lowers multipliers in chapters 1–10 so players who never replay get as far as before, ~chapter 10), `recommend`. Casual 3/3 complete in 1,440 fights with 0 losses; hardcore 3/3; greedy stalls between chapters 6 and 13 (was ~10).
